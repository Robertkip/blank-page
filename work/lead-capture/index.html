Case 1 · FlyRank backend capstone

A lead-capture API that stays up when the public internet hits it

Python · FastAPI · PostgreSQL · Docker 79 tests · 23/23 live probes View the repo

Context

A business defines a form widget in an authenticated dashboard, pastes one <script> tag onto any website, and the leads it captures arrive validated, spam-filtered, geo-enriched and queryable.

Constraint

The submission endpoint is reachable by the entire public internet. So the client is never trusted, the traffic is never predictable, and a broken dependency has to degrade the response rather than destroy it.

What I did

  • Defended the front door: payload validation that returns a clean 4xx (never a 500), an origin allow-list, per-IP and per-widget rate limits, and honeypot plus fill-time spam checks.
  • Made dependencies optional: geo enrichment tries provider A, falls back to provider B, and stores the lead anyway if both fail.
  • Kept side effects out of the request: the lead and its email/webhook job are written in one transaction, and a background outbox worker retries with exponential backoff, then dead-letters and alerts.

Evidence

Outcome

All six acceptance probes pass: 23 assertions, 0 failures. Bad payloads get a 4xx, floods get a 429 while the API stays up, bots are silently dropped, and a failing email or webhook can never turn a successful submission into an error.
