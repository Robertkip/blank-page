Case 3 · FlyRank internship, week 7

A language model behind a contract it isn't allowed to break

Python · FastAPI · Ollama / OpenRouter 8/8 on a hand-labelled eval View the repo

Context

My scraper collected 60 books with titles, prices and blurbs, but no genre, because the pages never stated one. A person can read a blurb and say "that's a thriller" in two seconds. POST /enrich does that in code: genre from a fixed list of ten, audience, a one-sentence summary and data-quality flags.

Constraint

Language models don't reliably follow instructions. The caller must never receive text the model wrote directly: only values this API has checked, in exactly the promised shape.

What I did

  • A strict schema: every answer is validated. If it doesn't fit, the model is told exactly what was wrong and gets one more try. If it fails again, the caller gets a clear error and the bad answer goes to a quarantine file for a human.
  • My own retry logic: I turned off the SDK's silent retries, so one request is one model call unless I decided otherwise.
  • An honest eval: eight cases hand-labelled from real scraped records before any were run, including two deliberately hard ones. One has an empty blurb and must answer with low confidence, not a confident guess.

Evidence

Outcome

8/8 on category with qwen2.5:7b, against 2/8 for llama3.2:1b on the same prompt and cases.

The honest asterisk: the first run scored 7/8. The miss wasn't a wrong answer. The first case timed out while the model was still loading into memory. I report both, because the cold-start failure is the number that would wake someone up at 3am.
